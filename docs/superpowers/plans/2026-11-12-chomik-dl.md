# chomik-dl Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A LAN-only web app where you paste a chomikuj.pl file URL and a background worker logs in, clicks through Pobierz → popup, and streams the file into `/downloads`.

**Architecture:** FastAPI serves one HTML page and a small JSON API. Jobs live in SQLite. A single asyncio worker takes one job at a time: Playwright (headless Chromium, persisted session) resolves the real file URL by clicking through the site and cancelling the browser download; httpx then streams that URL with the browser's cookies/headers into a `.part` file with progress. All site-specific selectors live in one module, and the browser flow is tested against a local fake chomikuj site.

**Tech Stack:** Python 3.12+ (Docker image) / 3.14 (dev), FastAPI, uvicorn, Playwright (async), httpx, sqlite3 (stdlib), pytest, pytest-asyncio, Docker Compose.

**Spec:** `docs/superpowers/specs/2026-11-06-chomik-dl-design.md`

## Global Constraints

- Env vars: `CHOMIKUJ_LOGIN`, `CHOMIKUJ_PASSWORD`, `CHOMIKUJ_BASE_URL` (default `https://chomikuj.pl`), `DOWNLOAD_DIR` (default `/downloads`), `DATA_DIR` (default `/data`), `MIN_JOB_GAP_SECONDS` (default `20`), `HUMAN_PAUSE_MIN`/`HUMAN_PAUSE_MAX` (default `1.0`/`4.0`), `HEADLESS` (default `true`; `false` lets the user log in by hand once to clear a captcha).
- Browser identity: realistic desktop Chrome UA without "HeadlessChrome", locale `pl-PL`, `Accept-Language: pl-PL,pl;q=0.9,en;q=0.8`, timezone `Europe/Warsaw`, viewport `1920x1080`, launch arg `--disable-blink-features=AutomationControlled`. httpx reuses the same UA and Accept-Language.
- One job at a time; at most 1 retry per job, with backoff; never solve captchas; no proxies.
- Failure codes (exact strings) and messages shown in UI:
  `invalid_url` "Not a chomikuj.pl file link", `login_failed` "Login failed — check CHOMIKUJ_LOGIN/PASSWORD", `captcha` "Login needs captcha — log in manually (see README)", `out_of_transfer` "Out of transfer on this account", `password_protected` "File is password-protected", `not_found` "File not found or removed", `timeout` "chomikuj did not respond in time", `download_failed` "Download interrupted".
- Downloads write to `<name>.part` and rename on completion; name collisions get ` (1)`, ` (2)` … before the extension.
- Compose publishes the port as `${BIND_ADDR:-127.0.0.1}:${PORT:-8080}:8080`; README tells the user to set `BIND_ADDR` to the homelab's LAN IP. No auth on the page.
- No captcha solving, no stealth plugins, no IP rotation.

## Review Focus

1. A URL with tracking query/fragment (`…/plik.rar,123.rar(archive)?foo#bar`) or `www.`/`m.` subdomain must be accepted and normalised; a non-chomikuj host must be rejected → test in Task 2.
2. Server killed mid-download: on restart the job must be `queued` again and the stale `.part` removed, never shown as done → test in Task 3.
3. Expired session cookie (logged-out page shown where logged-in was expected) must trigger one re-login, not a `login_failed` → test in Task 5.
4. Server sends no `Content-Disposition` and no `Content-Length` → filename falls back to the page's file name, progress shows bytes without percent → test in Task 4.
5. Filename containing `/`, `..` or Windows-illegal chars from the site must not escape `DOWNLOAD_DIR` → test in Task 4.

### Task 4: Filenames and streaming downloader

**Files:** Create `app/files.py`, `app/downloader.py`, `tests/test_files.py`, `tests/test_downloader.py`

**Interfaces:**
- Produces:
  - `sanitize_filename(name: str) -> str` — strips path components, replaces `<>:"/\|?*` and control chars with `_`, trims dots/spaces, never empty (`"download"`), max 200 bytes keeping extension.
  - `filename_from_content_disposition(header: str|None) -> str|None` — supports `filename*=UTF-8''…` (preferred) and `filename="…"`.
  - `unique_path(directory: Path, name: str) -> Path` — `name`, then `stem (1).ext`, `stem (2).ext`…; also treats an existing `.part` as taken.
  - `async stream_download(url: str, *, cookies: dict[str,str], headers: dict[str,str], dest_dir: Path, fallback_name: str, on_progress: Callable[[str,int,int|None],None], client: httpx.AsyncClient|None = None) -> Path` — picks name (Content-Disposition → fallback), writes `<final>.part` in 1 MiB chunks, calls `on_progress(filename, done, total)` at most every 0.5 s and at end, renames to final; on any error deletes `.part` and raises `ChomikError("download_failed")`; HTTP 404 → `not_found`.

- [ ] **Step 1: Failing tests (files):** `sanitize_filename("../../etc/passwd") == "passwd"`; `sanitize_filename('a<b>:c?.txt') == "a_b__c_.txt"`; `sanitize_filename("..") == "download"`; Content-Disposition `attachment; filename*=UTF-8''za%C5%BC%C3%B3%C5%82%C4%87.zip` → `"zażółć.zip"`; `filename="x.rar"` → `"x.rar"`; `None` → `None`; `unique_path` with `a.zip` and `a (1).zip.part` existing → `a (2).zip`.
- [ ] **Step 2: Failing tests (downloader)** using `httpx.MockTransport`: full download writes correct bytes, name from Content-Disposition, no `.part` left, last progress call has `done==total`; no Content-Disposition/no Content-Length → uses `fallback_name`, progress `total is None`; transport raising mid-stream → `ChomikError("download_failed")` and no files left in dir; 404 → `not_found`; malicious Content-Disposition `filename="../../x"` lands inside `dest_dir` as `x`.
- [ ] **Step 3:** Run → FAIL. **Step 4:** Implement. **Step 5:** Run → PASS. Commit `feat: safe filenames and streaming downloader`.

### Task 5: Fake chomikuj site + BrowserSession

**Files:** Create `app/humanize.py`, `app/browser/__init__.py`, `app/browser/selectors.py`, `app/browser/session.py`, `tests/fake_site/app.py`, `tests/fake_site/__init__.py`, `tests/conftest.py`, `tests/test_session.py`

**Interfaces:**
- Consumes: `Settings`, `ChomikError`.
- Produces:
  - `async human_pause(settings: Settings) -> None` (random uniform in `[pause_min, pause_max]`; tests set both to 0).
  - `selectors.py`: constants `LOGIN_INPUT='input[name="Login"]'`, `PASSWORD_INPUT='input[name="Password"]'`, `LOGIN_SUBMIT`, `LOGGED_IN_MARKER`, `CAPTCHA_MARKER`, `DOWNLOAD_BUTTON` (the Pobierz button on file page), `POPUP_CONFIRM_BUTTON`, `FILE_NAME` (file title on page), `TEXT_OUT_OF_TRANSFER`, `TEXT_PASSWORD`, `TEXT_NOT_FOUND`. Initial values are best guesses from the live site (homepage form fields confirmed: `Login`, `Password`, `__RequestVerificationToken`); user verifies them with a real account.
  - `Resolved` dataclass: `url: str, cookies: dict[str,str], headers: dict[str,str], suggested_name: str`.
  - `BrowserSession(settings: Settings)`: `async start()`, `async close()`, `async resolve(file_url: str) -> Resolved`. Uses `launch_persistent_context(user_data_dir=settings.data_dir/"browser", headless=settings.headless, args=["--disable-blink-features=AutomationControlled"], user_agent=UA, locale="pl-PL", timezone_id="Europe/Warsaw", viewport={"width":1920,"height":1080}, extra_http_headers={"Accept-Language": ACCEPT_LANGUAGE}, accept_downloads=True)`. `UA` and `ACCEPT_LANGUAGE` are module constants in `session.py` (UA: current stable desktop Chrome on Windows 10, e.g. `Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/<current major>.0.0.0 Safari/537.36`).
- `resolve` algorithm: goto file URL → if not `LOGGED_IN_MARKER`: login (goto base, fill, human_pause, click submit; `CAPTCHA_MARKER` → `captcha`; still not logged in → `login_failed`) then goto file URL again (this is the single re-login for expired sessions) → `TEXT_NOT_FOUND`/404 → `not_found` → read `FILE_NAME` → human_pause → click `DOWNLOAD_BUTTON` → wait for either `POPUP_CONFIRM_BUTTON` or a download event; inspect popup text for `TEXT_OUT_OF_TRANSFER`/`TEXT_PASSWORD` → raise; else human_pause, click confirm inside `page.expect_download()` → take `download.url`, `await download.cancel()` → return `Resolved` with cookies from `context.cookies(download.url)`, headers `{User-Agent, Accept-Language, Referer: file_url}`. Any Playwright `TimeoutError` → `timeout`. On any failure, save a screenshot to `settings.data_dir/"last_error.png"` (test: `test_not_found` also asserts the file exists).

### Task 6: Worker

**Files:** Create `app/worker.py`, `tests/test_worker.py`

**Interfaces:**
- Consumes: `JobStore`, `BrowserSession.resolve`, `stream_download`, `Settings`.
- Produces: `Worker(settings, store, session, download=stream_download)` with `async run_forever()`, `async run_once() -> bool` (processes one queued job, returns False if none), `wake()` (sets an `asyncio.Event` so new jobs start without waiting).
- Behaviour: `resolving` → `resolve` → `downloading` (progress via `store.update(bytes_done, bytes_total, filename)`) → `done`. On `ChomikError` with code in `{timeout, download_failed}` and `attempts < 2`: requeue after backoff (`30 s`, test overrides via constructor `retry_backoff=0`); otherwise `failed` with code + message. Unexpected exceptions → `failed`, code `download_failed`, logged with traceback. After every job wait `min_job_gap` before the next.
